# Skill名称：铜周期研判Skill
## 基础信息
- 版本：v1.0
- 描述：把「铜现在处在什么阶段」拆成 4 个宏观顺风因子 + 4 个位置动量因子，输出读数 + 评分 + 九宫格阶段 + 信号命中 + 结论失效条件。**数据型技能**——只出判定，不产出报告。
- 所属分类：数据分析
- 适用场景：工业金属/顺周期板块择时、大类资产配置里的铜权重判断、「铜现在能不能买 / 什么位置 / 铜价怎么看」这类问题

## 关联文件
- 工具注册入口：./main.py
- 计算引擎：`thesis/engine.py`（Web 台账页复用同一套，勿在技能层重复实现）
- 台账定义（阈值可手改）：`data/thesis/cu_regime.json`
- 定义加载与校验：`thesis/defs.py`
- 原始研究：用户资料库《铜周期研判-README》（web 节点 prRkVYKYVe9MuCLzX3GjRX）与配套源码 cu_regime.py / cu_config.json
- ⚠️ **同目录兄弟技能**：`gold_env`（贵金属）、`hog_env`（农业/养殖）——三者共用 `ThesisSkill` 薄封装，**阈值符号绝不可互相照抄**（资产属性不同，方向可能相反）

## 目录层信息
- 关键参数：无（因子与阈值全部来自台账定义）
- 核心目标：按定义取数 → 区间打分 → 阶段判定；数据缺失标 `score=null`，不静默给 0 分
- 数据来源：`macro_indicator` 长表（沪铜主连 CU0 / 螺纹钢主连 RB0 / 上海金 Au99.99 / 合成美元指数 dxy / 美债 10Y / 中国 10Y）；位置维度由沪铜自算（延伸度分位 / 年均线偏离 / 动量分位）

## 工具列表
### 工具1：get_cu_env
- 功能：获取铜周期研判读数与综合判定
- 调用入口：main.py.build_tools 中的 get_cu_env
- 参数约束：无参数
- 返回结构：
  - `factors[]`：每项 `key/name/value/unit/score/status/detail/source/asof/stale/note/confidence`
    - `score` ∈ {-2,-1,0,1,2}，**null = 数据缺失，不等于中性**
    - `stale=true` → 引用时必须标注数据截止日（`asof`）
  - `total` 综合总分（仅统计有效因子，8 项满分 ±16）、`valid_count` / `factor_count`
  - `verdict` / `action`：结论档位与对应动作
  - `stages`：**阶段矩阵（本台账的核心输出）**
    - `stage` 当前阶段名（9 个之一）/ `desc` 含义 / `tone` 方向（bull/warn/neutral/bear）
    - `drive_total` 驱动力（四宏观因子之和，满分 ±8）/ `drive_band`（顺风 / 中性 / 逆风）
    - `pos_total` 位置动量（四因子之和，满分 ±8）/ `pos_band`（低位 / 中位 / 高位）
    - `pos_keys`（四因子 key 列表）/ `complete` 两轴是否全部因子有效 / `drive_missing` / `pos_missing`
    - `cells[]` 九宫格全部格子（`current=true` 即当前格）
  - `signals.buy[]` / `signals.warn[]`：`label/current/hit`
  - `invalidation[]`：`text/current/hit` —— **结论失效条件，命中即说明多头结论不再成立**
  - `scenarios[]` / `transmission[]` / `phases[]`：情景推演 / 传导链路 / 历史阶段（均不参与打分）
  - `metric_values`：各指标原始读数（供交叉引用）
  - `warnings[]`：取数降级、数据陈旧等提示
- `factors` 的 key 固定为：`dxy`（美元指数）/ `us10`（美债 10Y）/ `cn10`（中国 10Y）/ `rb`（螺纹钢）/ `rank`（铜价延伸度分位）/ `ma`（年均线偏离）/ `mom`（20 日动量分位）/ `cuau`（铜金比变化）

### 工具2：describe_cu_thesis
- 功能：返回台账元信息（名称、标的口径、因子清单、结论档位、定义校验问题）
- 参数约束：无参数
- 使用时机：用户问「这个台账怎么算的 / 有哪些因子」时用；**不要**用它取当前读数

## 使用指南

### 适用场景
- 用户问「铜/沪铜现在什么位置、能不能买」→ 先取本因子包，再结合估值与持仓
- 板块择时：作为「工业金属环境是否顺风」的定量输入
- **结论失效条件必须一起呈现**：不能只报总分，命中失效条件时须显式说明

### 不适用场景
- 不选个股（铜矿股、有色 ETF 的选股是选股流程的职责，本技能只给环境）
- 不做铜价点位预测（本台账给阶段与档位，不给目标价）
- 不提供买卖指令

### 输出解读要点（**口径诚实性，务必遵守**）
- **两个维度不可混为一个总分看**：`stages.stage` 才是本台账的主结论。
  「宏观顺风 + 位置已高」与「宏观顺风 + 位置便宜」总分相近（都是顺风档），
  但前者是「持有可以、追高不宜」、后者是「历史上最优的组合」——必须按 `stage` 表述。
- **B 轴（位置动量）方向：`pos_total` 正分 = 价格低位/便宜（有利），负分 = 价格高位/贵。**
  `pos_total = −5` **不是「不利」**，而是「价格已在历史高位」。
  该轴由 4 个因子**求和**（`pos_keys`：rank+ma+mom+cuau），不是单因子。
- **⭐ 与黄金台账的方向差异（最易出错处）**：铜是**分子端资产**（有实体需求与现金流），
  与美债 10Y **正相关**（实测 +0.170），与黄金（分母端，负相关 −0.261）方向相反。
  **不要把 gold_regime 的阈值符号照抄到本台账。**
- **④ 螺纹钢是全台账最强正相关（r=+0.361）**：中国地产基建需求的代理。它走强 = 需求改善
  = 宏观顺风（正分）。但行政性限产会短期切断「螺纹钢 → 中国需求」这一环节，属机制性风险。
- **① 美元指数与铜负相关（r=−0.347，加息期强化到 −0.485）**：美元走弱 = 分母转松 = 正分。
- **⑤ 铜价延伸度分位与 ⑥ 年均线偏离刻意保留两条**：前者是「延伸度的历史分位」
  （相对自身），后者是「延伸度本身」（相对均线）。分位高但偏离小 = 温和上行；
  分位不高但偏离大 = 异动。二者的分歧本身就是信息。
- **⑦ 20 日动量分位是逆周期取向**：分位高 = 短期涨幅已大 = 追高风险（负分），
  与「趋势跟随」逻辑相反，是本台账的明确设计。
- **⑧ 铜金比变化**：铜金比上升 = 实体属性接棒（相对有利），下降 = 货币属性主导。
  首跑实测 +11.00%（+2 分）。
- **主连换月跳价**：沪铜主连由主力合约拼接，跨月换月处存在跳价——看趋势与分位可靠，
  **看单点绝对价位需注意**。
- **⚠️ 因子权重已重标定**：原始 cu_regime.py 四个因子是 ±3 制（美元/螺纹钢/铜价分位/动量分位），
  本引擎上限为 ±2，故做**保序压缩**（3/2/0/−2/−3 → 2/1/0/−1/−2），档位边界原样保留。
  驱动力满分 8、位置满分 8（原各 ±10）。详见定义 `_说明_因子权重与重标定`。
- 相关性与 `stages` 的阈值切点是**主观设定**，引用时须说明这一点。

### 失败 fallback
- 返回 `{"error": ...}` 时优先检查：① `data/thesis/cu_regime.json` 是否完整；
  ② `macro_indicator` 表里的 `cu_main / rb_main / au_sge / dxy / us10_y / cn10_y`
  是否已同步（新库首次运行需先拉一遍）
- 部分因子 `score=null` 不算整体失败：用 `valid_count` 说明有效因子数继续分析；
  若 `stages.complete=false`，须显式说明「只累加了 N/M 个因子，档位可能偏移」
- `cu_main`（CU0 5288 行）与 `rb_main`（RB0 4252 行）为全量拉取，首次同步较慢属正常
- `cuau`（铜金比）依赖 `au_sge` 与 `cu0` 按**共同交易日**对齐，两者最后一天不同时会取较近的共同日

### 不要重试条件
- 同一轮对话内不要重复调用（单次调用已含全部 8 因子）
- 返回 `error` 时不要连读同参重试；接口不可达时重试无意义

### 阈值调整
- 改 `data/thesis/cu_regime.json` 的 `thresholds` / `params` / `stages`，**无需重启**（带 mtime 缓存）
- 阈值表格式：`[下限, 上限, 得分]`，下限含、上限不含；**得分范围必须 ≤ ±2**
  （引擎硬上限，超出会被定义校验拦下）
- 定义被改动后建议顺手跑一次 `thesis.defs.validate_def()` 确认无「区间未覆盖 / 得分超范围」问题
- 若改动了 `stages.drive_keys` 或 `pos_keys`，务必同步复核 `drive_full` / `pos_full`
  与 `verdicts` 的 `min_total` 档位（量纲变了档位含义会整体漂移）
